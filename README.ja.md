# BGI / Ethornell 向け JXL Hook & Launcher

[English Document](README.md)

BGI / Ethornell エンジンを採用した 32bit ビジュアルノベルゲーム向けの汎用 JPEG XL (JXL) 画像展開互換レイヤーです。

ゲームアーカイブ内の画像を JXL 形式に再圧縮した際、メモリ上でエンジンの CBG 展開ルーチンをフックし、`libjxl` を用いて透過的にデコードします。JXL 化されていないオリジナルの画像リソースは、そのまま既存の展開処理（トランポリン）へフォールバックされるため、完全な後方互換性を保持します。

---

## 主な機能

- **インメモリ CBG 展開フック**: プロローグのシグネチャスキャン（`55 8B EC B8 FC 33 00 00`）により CBG 展開関数を特定してフックするため、特定のゲーム実行ファイルやバージョンに依存せず動作します。
- **透過的 JXL デコード**: `JXLCBG01` ヘッダが付与されたペイロードを検出し、エンジンネイティブの BGRX ピクセルバッファへ高速展開します。標準の CBG 画像はオーバーヘッドなく元の展開処理へ委譲されます。
- **2 種類の導入形態**:
  - **DirectInput8 プロキシ (`dinput8.dll`)**: 通常のネイティブ実行ファイル向け。ゲームフォルダへ配置するだけで動作し、ランチャーは不要です。
  - **汎用ランチャー (`bgi_launcher.exe`)**: Enigma Virtual Box などの仮想化パッカーによりシステム DLL 読み込みのハイジャックが無効化されている環境向け。展開完了のタイミングを同期検知して安全に DLL を注入します。

## なぜ JPEG XL なのか？（圧縮効率とベンチマーク実績）

ビジュアルノベルゲームの画像アーカイブは、レガシーな圧縮アルゴリズム（従来の CBG に採用されている LZSS / RLE 拡張など）の限界により、ディスク容量が肥大化しがちです。JPEG XL を導入することで、Butteraugli 視覚心理モデルによる**極めて高い視覚的無劣化品質（Visually Lossless）を維持したまま、画像容量を 90% 以上削減**することが可能になります。

### 実ゲームリソースにおける検証実績（1,796 枚の画像バッチ）

本プロジェクトによる全量アーカイブ変換テスト（設定値: `quality=90`, `effort=8`）の実測データです：

| 評価項目 | 従来の BGI CBG（オリジナル） | JPEG XL レイヤー（本プロジェクト） | 改善率 / 削減効果 |
| :--- | :--- | :--- | :--- |
| **対象画像ペイロード** | **4,095.1 MB** (~4.10 GB) | **393.8 MB** (~0.39 GB) | **-90.24% 削減 (約 10.4 分の 1 に軽量化)** |
| **ゲーム全体容量 (音声・動画含む)** | **9,634.9 MB** (~9.63 GB) | **5,933.6 MB** (~5.93 GB) | **-38.42% 全体削減 (-3.70 GB のディスク節約)** |
| **最大チャンネル誤差 (0–255)** | 0 (ビット完全一致) | **1** | 人間の視覚上完全に判別不能 |
| **二乗平均平方根誤差 (最大 RMSE)** | 0.0000 | **0.5668** | 数学的にサブピクセル未満の極小誤差 |
| **視覚品質 (Butteraugli モデル)** | 基準値 | **完全な視覚的無劣化** | リンギングやバンディングの発生ゼロ |
| **SIMD ハードウェアアクセラレーション** | x86 スカラー処理 | **Google Highway 経由 AVX2 / AVX-512** | 瞬時のロード・デコード速度 |

### 主要画像フォーマットとの比較

| 評価項目 | 従来の CBG | WebP | AVIF | JPEG XL (JXL) |
| :--- | :--- | :--- | :--- | :--- |
| **CBG 比の圧縮率** | 基準 (0%) | 約 50% – 65% | 約 75% – 82% | **> 90% (圧倒的)** |
| **アニメ調線画・微細ディテール** | 可逆（ただし肥大） | 輪郭のぼやけ・滲みが発生 | 色差間引きによるぼやけ | **シャープな線画と滑らかなグラデーションを保持** |
| **暗部バンディング・ブロックノイズ** | なし | 暗部で階調飛びが目立ちやすい | 低レート時にブロックノイズ | **アーティファクトほぼ皆無 (Butteraugli 評価)** |
| **32bit x86 環境での展開速度** | 単一スレッド LZSS | 標準 libwebp | CPU 負荷が高く重い | **Google Highway による SIMD 高速展開** |
| **エンジン内部バッファ (BGRX) 供給** | 変換オーバーヘッド要 | 変換オーバーヘッド要 | 変換オーバーヘッド要 | **エンジンの ABI メモリへ直接展開供給** |

> **検証結果のまとめ**: 1,796 枚の高解像度グラフィックを変換した結果、画像アーカイブのサイズは **4.1 GB から 400 MB 未満へと劇的に縮小**し、ゲーム全体で **3.7 GB のストレージを削減**しながら、画質劣化のない体験を実現しています（最大画素誤差 $\le 1$、RMSE $< 0.57$）。

## 導入方法 & ランチャー仕様

### モード 1: 通常のネイティブ実行ファイル（プロキシモード）
オリジナルのゲーム実行ファイル向け：
1. `build/` 内の `dinput8.dll` および実行時依存ファイル（`libjxl.dll`、`libhwy.dll`、`libbrotli*.dll` など）をゲームのルートディレクトリ（`bgi.exe` と同階層）へコピーします。
2. 通常通りゲームを起動します。

### モード 2: 仮想化実行ファイル（ランチャーモード）
Enigma Virtual Box などでパッケージングされた環境向け：
1. `bgi_launcher.exe`、`bgi_jxl_hook.dll`、および実行時依存ファイルをゲームフォルダへコピーします。
2. `bgi_launcher.exe` からゲームを起動します。

#### ターゲット実行ファイルの解決順序
`bgi_launcher.exe` は以下の決定論的な順序で対象のメイン実行ファイルを検索・特定します：
1. **コマンドライン引数**: `bgi_launcher.exe [game.exe]` のように明示的に指定されたパス。
2. **設定ファイル**: `launcher.ini` で指定されたターゲット：
   ```ini
   [Launcher]
   Target=game.exe
   ; 任意: 注入前に読み込み完了を待機するコンパニオン DLL 名
   MilestoneDll=companion.dll
   ```
3. **順序優先の自動推導**:
   - 同ディレクトリ内のすべての `.exe` を走査。
   - 補助ツール類を除外（キーワード: `launcher`、`hook`、`setup`、`install`、`unins`、`config`、`cfg`、`update`、`test`、`tool`、`dump`、`arc20`、`repack`）。
   - 標準エンジン名（`bgi.exe`、または `bgi` / `ethornell` を含む名称）を優先。
   - 残りの候補をファイルサイズ降順でソート（補助ツールに比べメインプログラムは大容量であるため、最大サイズのプログラムを最優先として選択）。

#### 仮想化環境の同期注入
対象バイナリに `.enigma` セクションが検出された場合：
1. プロセスを通常起動し、モジュール読み込み状況を監視します。
2. 仮想化環境の展開およびコンパニオン DLL のロード完了を検知した瞬間、主スレッドを一時停止（`SuspendThread`）します。
3. リモートスレッド（`CreateRemoteThread` + `LoadLibraryW`）により `bgi_jxl_hook.dll` を安全に注入します。
4. ゲームが最初の画像ファイルを読み込む前に主スレッドを再開（`ResumeThread`）します。

## ビルド手順

必要環境：
- 32bit MinGW-w64 ツールチェーン（i686）
- 32bit `libjxl` 開発用ライブラリ

```powershell
# デフォルトビルド（プロキシモード専用: dinput8.dll、依存ライブラリ、テストを生成）
pwsh -File ./build.ps1

# フルビルド（bgi_launcher.exe および bgi_jxl_hook.dll を含めて生成）
pwsh -File ./build.ps1 -WithLauncher

# ランチャーのみの高速ビルド
pwsh -File ./build.ps1 -LauncherOnly

# テストスイートのみビルド
pwsh -File ./build.ps1 -TestOnly
```

スタンドアロン検証テストの実行：
```powershell
./build/hook_test32.exe ./build/dinput8.dll <path_to_sample.cbgjxl>
```

## 画像仕様 (Image Contract)

- **変換対象**: 24bit CBG type 1（不透明 BGR24）、オフセット 22 のフラグが `0` のリソース。
- **ヘッダカプセル化**: 先頭 16 バイトの BGI 画像メタデータを保持し、プレフィックス `CompressedBG___` および識別子 `JXLCBG01` を付与。
- **デコード出力**: 16 バイトヘッダ + BGRX ピクセルデータ（depth 32、format 7）。
- 通常の CBG 画像は元のエンジントランポリン経由で無劣化・等速展開されます。
